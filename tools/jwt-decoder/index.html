About the JWT Decoder

A JSON Web Token (JWT) carries claims such as the user ID, roles and expiry time, encoded as three Base64URL sections separated by dots: header, payload and signature. This decoder splits a token, shows the readable header and payload, and tells you whether the exp claim has passed. It decodes locally and does not verify the signature, because verification needs the secret or public key, which you should never paste into a website.

When to use it

  • Inspecting what claims an identity provider put in a token while debugging login.
  • Checking whether an access token has expired.
  • Confirming the signing algorithm in the header during an integration.
💡 Pro tip

Decoding is not verifying. Never trust a token's contents without verifying its signature on your server using the correct key.

Frequently asked questions

Does this verify the signature?

No. It only decodes the header and payload. Signature verification must be done by your backend with the proper key.

Is it safe to paste a token here?

Decoding happens in your browser and nothing is sent to us. Still, avoid pasting live production tokens into any website, and revoke any token you have shared.

Why can anyone read a JWT's contents?

The payload is only Base64URL encoded, not encrypted. Never put passwords or secrets inside a JWT.
